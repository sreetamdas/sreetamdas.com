- SSR
- streaming
- server routes

- middleware

---

# Server functions / server routes

```tsx
const getStats = createServerFn({ method: "GET" })
  .validator(parseStatsInput)
  .handler(async ({ data }) => loadStats(data));
```

- functions: app-to-server RPC
- routes: public HTTP endpoints
- `GET` when the call should be cacheable

---

# Middleware across the boundary

```tsx
const boundaryMiddleware = createMiddleware({ type: "function" })
  .client(async ({ next }) => next({ context: { source: "browser" } }))
  .server(async ({ next }) => next({ context: { requestId: crypto.randomUUID() } }));
```

- `.client()` before the call leaves the browser
- `.server()` before the handler runs

---

# Loader data is cached

```tsx
createFileRoute("/blog/$slug")({
  loader: ({ params }) => getBlogRenderable({ data: params }),
  staleTime: 1000 * 60 * 60 * 24,
});
```

Caching moves back to the route.

---

# Rendering is a dial

```tsx
createFileRoute("/slides/tanstack-start/dev-lab")({
  ssr: true,
});
```

Full SSR, data-only, or client-only — per route.

---

# Streaming SSR

```tsx
loader: async ({ deps }) => ({
  shell: await getFastData(deps),
  slowPanel: getSlowData(deps),
});
```

Return an un-awaited promise.

---

# Build-time server functions

```tsx
export const getHighlightedCode = createServerFn({ method: "GET" })
  .middleware([staticFunctionMiddleware])
  .handler(async () => loadRwcCodeSamples());
```

Same primitive. Different clock.

---

# One route, many choices

```tsx
createFileRoute("/stats")({
  validateSearch,
  loaderDeps: ({ search }) => search,
  loader: ({ deps }) => getStats({ data: deps }),
  staleTime: 1000 * 60 * 5,
});
```

- typed URL state
- server function
- caching
- rendering choice

# Type safety, the old way vs. Start

<TypeSafetyBuildUp />

<Steps>

- Next Pages: `FoobarPageQuery extends ParsedUrlQuery`, `params!`, `InferGetStaticPropsType` — just to give `params` a type
- Next App Router: every page redeclares `type PageParams = { params: Promise<...> }` and `await`s it — by hand, per route
- Start: one `validateSearch` schema; `useSearch()` returns `PlausibleDateRange` — no `as`, no `params!`

</Steps>

# TanStack + Vite

The stack is composable, and the ecosystem is open.

<Steps>

- Router → Query → Table → Start — the same headline primitives, composing together
- The TanStack Query and Table I already use at work, plus TanStack DB

# Deployment is part of the design

This site runs on Cloudflare Workers.

<Steps>

- D1 for page views and likes
- KV for runtime storage

- Smart Placement, logs, traces, version metadata

# How to start

<Steps>

- TanStack CLI connects setup, docs, add-ons, and generated changes
- Use it to scaffold, search docs, and choose integrations
- Add a server function, a `validateSearch`, a loader — incrementally
- The mental model never inverts: you opt _into_ the server

</Steps>
